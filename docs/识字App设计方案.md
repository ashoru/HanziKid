# 儿童识字 iPad App — 整体设计与功能规划

> 工作名：**认字啦 / HanziKid**（暂定）
> 目标设备：iPad（横屏优先，竖屏兼容）、iPadOS 17+
> 使用对象：孩子（4–9 岁，识字启蒙 / 小学低年级）+ 家长（录入、监督）

---

## 1. 产品定位

一句话：**拍一张照片，把孩子要学的字变成一套会自己安排复习的识字卡片。**

三个不可替代的价值点：

| 价值 | 说明 |
|---|---|
| 录入零门槛 | 拍照 → OCR 自动切字 → 家长勾选确认，10 秒建好一课字表 |
| 内容自动化 | 拼音、笔画数、笔顺动画、部首、结构、组词、成语、例句、易错点，全部自动生成，不用家长查字典 |
| 科学复习 | 内置间隔重复算法（记忆曲线），只练该练的字，每天 10–15 分钟 |

不做的事（划清边界，避免做成大杂绘）：
- 不做通用字典 / 不做汉语大词典浏览
- 不做社交、不做排行榜（儿童产品里的攀比是负资产）
- 不做付费内容商城

## 2. 用户与核心场景

**角色 A：家长（录入者 + 教练）**
- 每周 1–2 次，从语文课本 / 作业本 / 绘本拍照，或手动输入，生成一课字表
- 检查 AI 生成的内容（尤其成语、释义），有错一键改
- 看每周报告：学了几个字、哪些字反复错、掌握曲线

**角色 B：孩子（学习者）**
- 每天打开 App，看到"今天的任务：3 个新字 + 8 个复习"，一条进度条走完就结束（不可无限刷）
- 每个字一页：大字 + 笔顺动画 + 听发音 + 组词 + 小练习
- 自评"会了 / 有点忘 / 不会"，系统据此调整下次出现时间
- 完成后得到贴纸 / 小星星（轻奖励，不搞重养成）

**角色 C（隐含）：家长模式** — 进入字库管理、统计、设置需过一道"家长锁"（算术题门），防误删、防孩子乱改。

## 2.5 两个孩子：多档案 + 双难度（本产品的关键约束）

实际使用是 **5 岁（幼儿园中班，启蒙）+ 10 岁（四年级，拓展）** 两个孩子共用一个 iPad，所以在设计上必须满足：

### 2.5.1 多档案（Profile）
- 首页先选"谁在学"（大头像切换，一眼可辨）
- **字卡内容共享，学习进度隔离**：
  - `CharacterCard`（拼音/部首/笔画/笔顺）全库唯一，一份数据
  - `Deck`、`SRSState`、`ReviewLog` 按 profile 隔离 —— 老二学到"树"不影响老大的"树"复习进度
  - 老大录过的字，老二可以直接挑来学（"从哥哥的字表里挑"）
- 家长报告、每日上限、发音语速、提醒时间都按 profile 独立配置

### 2.5.2 双难度（Level A / Level B）
同一张字卡，按档案显示不同深度的内容（`CharacterContent` 按 level 存两套）：

| 维度 | **Level A · 5 岁启蒙** | **Level B · 四年级拓展** |
|---|---|---|
| 学习目标 | 认得形、读准音、有兴趣 | 会读、会写、会用在句子里 |
| 内容 | 大字 + 拼音 + 部首 + 笔顺动画（看，不强制写）+ 1–2 个词 + 1 句生活例句 | 全部内容：多音字提示、4–6 个词（含搭配）、2 个成语 + 释义 + 造句、近/反义词、易混字辨析、字源 |
| 是否显示成语 | 否（折叠隐藏） | 是 |
| 主要题型 | 听音选字、看字自评、图字配对 | 看拼音选/写字、组词填空、成语释义匹配、**易混字辨析**、**听写** |
| 每日新字 | **2–3 个** | **5–8 个** |
| 单次时长 | ≤ 10 分钟，做 4 种题型就够 | ≤ 15 分钟 |
| 反馈风格 | 贴纸、星星、音效多（重奖励） | 进度条、连续天数、错字本（轻奖励） |
| 每日任务封顶 | 硬封顶，做完锁屏 | 封顶但允许"再加 5 个字"（自驱） |

> 10 岁孩子的刚需是**听写/默写**：MVP 用"听音 → 在米字格里自己写（不显示底字）→ 系统比对描红覆盖率 + 家长一键判定"，P2 再上离线手写识别做自动判分。

### 2.5.3 字表来源（两个孩子各有侧重）
- **老二（中班）**：以《3–6 岁儿童常用字表》/ 生活识字（绘本、路牌、包装）+ 家长随手拍为主
- **老大（四年级）**：以部编版四年级课本生字、听写错字本、作文里写错的字为主 → 支持"错字本自动回流成字表"

## 3. 页面结构与信息架构

```
底部/L侧边导航（3 + 1 个）
├─ 今日        ← 默认落地页：任务卡 + 一键开始
├─ 字库        ← 字表分组（课本 / 生字 / 易错 / 全部字）、搜索、批量操作
├─ 报告        ← 家长模式：统计、掌握度、错字榜、导出
└─ 设置        ← 发音人/语速、每日新字上限、提醒时间、家长锁

核心二级页
├─ 拍照录入   拍照 → 框选 → OCR 候选字网格 → 勾选/剔除 → 归入字表 → 生成字卡（进度可见）
├─ 学习页（一页一字）★ 最重要
├─ 复习页     题组形式，一屏一题
├─ 字卡详情   单字的全部信息 + 家长编辑入口
└─ 奖励页     贴纸墙 / 连续天数
```

### 3.1 学习页：一页一字（核心页面）

竖屏/横屏布局示意（横屏：左侧汉字区 60%，右侧信息区 40%）：

```
┌───────────────────────────┬──────────────────────────┐
│                           │  ① 拼音  shù  🔊          │
│     米 字 格 大字          │  ② 部首 木 · 10画 · 左右结构│
│        「树」             │  ③ 笔顺动画 ▶（逐笔，可跟写）│
│   笔顺：一丨丶…            │  ────────────────────    │
│                           │  ④ 组词：树木 树叶 大树    │
│  [描红练一练]              │  ⑤ 成语：树大根深         │
│                           │     释义一句话            │
│                           │  ⑥ 例句（大字+高亮本字）    │
│                           │  ⑦ 小提示：别和"材"搞混    │
├───────────────────────────┴──────────────────────────┤
│  ← 上一个字    不会 😕   有点忘 🤔   会了 😀   下一个 → │
└──────────────────────────────────────────────────────┘
```

关键交互细节：
- **点字即读**（点大字/点拼音/点词，都发音）；长按大字 = 慢速重复读 3 遍
- 笔顺动画默认自动播放一遍，之后可"跟着描"（手指描红，笔画顺序错误时高亮提示下一笔）
- 三档自评是**唯一**需要孩子做的输入，其他全部只读 —— 降低操作负担
- 内容分区可折叠：默认只展开①②④⑥，成语和字源点了才展开（避免一页信息过载）
- 字体：楷体（教学标准字形），字号 ≥ 120pt；正文用系统圆体/黑体，加字距

### 3.2 复习页：一题一屏

题型库（同一字不同题型轮换，防止"看脸认字"）：

| 题型 | 适合 | 说明 |
|---|---|---|
| 看字读音（自评） | 新字首次 | 就是学习页的自评 |
| 听音选字 | 辨形 | 播报读音，4 选 1（干扰项取形近/音近字） |
| 看拼音选字 | 音形对应 | 上拼音，下 4 个字 |
| 组词填空 | 用词 | "树__"，选项：木/叶/林 |
| 笔顺描红 | 书写 | 描完自动判分（覆盖率 + 顺序） |
| 找不同/选错字 | 易混辨析 | "睛/晴/请" 三选一 |

默认规则：**首次复习用自评，进入复习阶段后 70% 客观题 + 30% 自评**。客观题答错 = Again，答对但超时 = Hard。

### 3.3 拍照录入流程（家长侧）

1. 拍照 / 从相册选 / 粘贴一段文字 / 选"教材字表"（内置部编版 1–2 年级生字表，可直接选课）
2. Vision OCR 识别中文 → 自动去重、过滤非汉字标点、按出现顺序排列
3. 候选字网格（大按钮，一点选中/取消），常用字自动预选
4. 选择目标字表（新建 / 追加到"第 3 课"）
5. 后台批量生成字卡（本地字库秒出 + 在线补充异步到达，带进度条）；生成完提示"3 个字的成语待确认"

## 4. 功能清单与优先级

### P0（MVP，能给孩子用起来）
- 拍照/手动录入 → 字表管理（增删、分组、排序）

- SM-2 式间隔重复调度 + 每日任务（新字上限、复习上限）

- 周报导出 PDF 给老师

## 5. 记忆曲线算法设计（核心）

### 5.1 模型选择
用 **SM-2 简化版**（Anki 同源，百词斩类产品的底层逻辑类似）。成熟、可解释、参数少，便于家长理解"为什么今天要复习这个字"。

每个字维护的状态：

```
state: new | learning | review | mastered | suspended
ease: 2.5（1.3–2.8）        // 难度系数
interval: 0 天              // 当前间隔
reps: 0                     // 连续正确次数
lapses: 0                   // 忘记次数
due: 日期
lastReviewedAt
```

### 5.2 三档自评 → 算法映射（面向儿童的调参）

| 孩子点击 | SM-2 质量 | 处理 |
|---|---|---|
| 😀 会了 | q=5 | ease +0.1；reps+1；interval = 首次 1 天 → 3 天 → interval×ease（上限 60 天） |
| 🤔 有点忘 | q=3 | ease −0.15；interval ×1.2（不低于 1 天） |
| 😕 不会 | q=1 | ease −0.2（下限 1.3）；reps 归 0；interval = 当天再练（10 分钟后再出现一次），明天再练；lapses+1 |

儿童适配的关键调整（与成人 Anki 的差别）：
- **间隔上限 60 天**（成人可以几年，孩子学字需要保持手感）
- **"当天重现"**：不会的字在本次 session 内 10 分钟后重现一次（短时巩固窗口）
- **每日新字上限按档案设**（5 岁档 2–3 个 / 四年级档 5–8 个），复习上限 15–20 个，超出自动延后（防疲劳）
- **全对连击奖励提前毕业**：连续 4 次 😀 且间隔 ≥ 21 天 → 标记 mastered，进"已掌握"，不再每日打扰（仍可手动抽查）
- **leech 处理**：lapses ≥ 4 的字进"重点字"专项，改成多题型反复练 + 让家长看提示（可能是形近混淆）
- **周末弹性**：漏一天不清零，只顺延（保留连续天数但显示"已补上"）

### 5.3 每日任务组装
```
今日任务 = min(到期复习, 复习上限) 排序（逾期最久优先、leech 优先）
        + min(未学新字, 新字上限) 排序（按字表顺序）
        + 到期"重点字"专项（最多 3 个）
```
所有上限按 profile 独立配置（见 2.5）。任务完成即锁屏 —— "一天就这么多"，避免刷屏式过量学习。

### 5.4 客观题替代自评的判分
- 选对且 < 4s → q=5；选对但慢 → q=4；选错一次后选对 → q=3；最终选错 → q=1
- 描红覆盖率 ≥ 80% 且笔顺正确 → q=5；顺序错 → q=3

### 5.5 未来可升级
数据量足够（≥ 5000 次复习记录）后可换 **FSRS**（更准，但参数需拟合）。架构上把调度器抽象成 `Scheduler` 协议，两套实现可切换、可 A/B。

## 6. 技术方案

> 2026-10-22 调整：为了支持 iOS 16.3（家里的 iPad），数据层从 SwiftData 换成 **Codable 值类型 + JSON 持久化**（`Services/AppStore.swift`），不再依赖 iOS 17。模型无关系查询需求（按 profileID / hanzi 取），值类型让 SwiftUI 更新和测试都更直接。


### 6.1 推荐栈：SwiftUI 原生（iPadOS 17+）

理由：这台机器有 Xcode 26.6，原生方案在 **OCR（Vision）、笔顺渲染（SwiftUI Path/WebView）、TTS（AVSpeechSynthesizer）、离线存储（SwiftData）、手指描红低延迟** 上都是最优；无需服务器，家长零运维。

```
App (SwiftUI, iPad 优先)
├─ 表现层    TodayView / StudyView / ReviewView / DeckView / ReportView
├─ 领域层    Scheduler(SM-2) · StudySessionEngine · CardContentResolver
├─ 数据层    AppStore: CharacterCard, Deck, SRSState, ReviewLog + JSON 持久化
├─ 能力层
│   ├─ OCRService        Vision (VNRecognizeTextRequest, zh-Hans, 离线)
│   ├─ StrokeService     本地笔顺数据 → hanzi-writer (WKWebView) 或原生渲染
│   ├─ SpeechService     AVSpeechSynthesizer(zh-CN) 离线 + 预生成 .m4a 缓存
│   └─ EnrichService     在线补充（词典 API / LLM 批量生成）→ 写回本地缓存
└─ 资源包    base_characters.json · strokes.json · 教材字表
```

### 6.2 字卡数据从哪来（分三层，先本地后在线）

| 层 | 内容 | 来源 | 是否需要网 |
|---|---|---|---|
| L1 基础字库（打包离线） | 拼音、部首、笔画数、结构、Unihan 释义 | 开源数据集（如 `chinese-xinhua` / Unihan / pinyin-data），预生成为 `base_characters.json`，覆盖 7000 常用字 | 否 |
| L2 笔顺 | 每字逐笔 SVG 路径 + 笔画类型 + 中线 | **Make Me a Hanzi**（Arphic 开源，CC-BY，含 9000+ 字笔画数据） | 否 |
| L3 扩展内容 | 组词、成语、例句、易错提示、字源小故事 | 预生成（离线批量跑一次 LLM，人工抽检）或家长设备端按需请求后**持久化缓存** | 是（可降级） |

> 关键工程决策：**L3 内容不实时生成**。孩子学习时必须 0 延迟、0 网络依赖。做法是"录入时后台批量生成 → 家长校对 → 落库"，生成失败的字先用 L1 数据顶着，标灰"内容待补全"。

### 6.3 发音
- 主：`AVSpeechSynthesizer` + `zh-CN` 高质量音色（系统级，离线）
- 缓存：每个字/词首次朗读后把音频写入缓存，重复播放无延迟
- 期待效果：点字 100ms 内出声。若系统 TTS 音色不满意，可选 Azure/火山 TTS 预生成整库音频（3500 字 × 3 种语速，约几小时离线跑一次）

### 6.4 笔顺动画与描红
- 路线 A（省事）：`hanzi-writer` 在 WKWebView 里跑，`HanziWriter.loadCharacterData` 用本地 JSON → 支持 `animateCharacter()` / quiz 模式（自带笔顺判错）
- 路线 B（体验更好）：把 hanzi 数据解析成 SwiftUI `Path` + 逐笔 duration 动画，原生描红判分（覆盖率 + 顺序 + 拐点）
- MVP 用 A，P2 换 B

### 6.5 存储与同步
- SwiftData 本地库；`ReviewLog` 只追加，用来算统计和日后换算法
- 可选 CloudKit 私有库同步（家庭共享走 `CKShare`，P2 再做）

### 6.6 数据模型草案

```swift
@Model Profile {                 // 两个孩子各一条
  name: String; avatar: String
  level: Int                   // 1 = 5岁启蒙(A) / 2 = 四年级(B)
  dailyNewLimit: Int; dailyReviewLimit: Int
  speechRate: Double; reminderTime: Date?
}

@Model CharacterCard {           // 全库唯一，按 hanzi 去重
  hanzi: String            // 唯一
  pinyin: String
  radical: String
  strokeCount: Int
  structure: String        // 左右/上下/独体…
  hasStrokeData: Bool      // 笔顺数据是否覆盖
}

@Model CharacterContent {        // 同一字按 level 存两套内容（见 2.5.2）
  hanzi: String; level: Int
  words: [String]          // 组词（A: 1–2 个 / B: 4–6 个含搭配）
  idioms: [Idiom]          // 成语 + 释义 + 造句（A 档为空）
  exampleSentence: String
  synonyms: [String]; antonyms: [String]   // 近/反义词（B 档）
  confusable: [String]     // 易混字（B 档重点）
  story: String?           // 字源
  enriched: Bool           // L3 是否已生成
  reviewedByParent: Bool   // 家长是否已校对
}

@Model Deck { profileID, name, kind(课本/听写错字/自定义), createdAt, orderIndex, cards: [CharacterCard] }

@Model SRSState {         // 按 profile × card 隔离
  profileID; hanzi
  state: String; ease: Double; intervalDays: Int; reps: Int; lapses: Int; due: Date; lastReviewedAt
}

@Model ReviewLog { profileID, hanzi, reviewedAt, grade(1/3/5), questionType, durationMs, isCorrect }

@Model AppSettings { parentPIN, voiceName, childLockEnabled, eyeRestMinutes }
```

```
├─ HanziKidTests/            调度器单元测试（最重要）
└─ Tools/                    Python 脚本：抓取/清洗字库、LLM 批量生成 L3 内容
```

## 7. 交互与视觉原则（儿童向）

1. **大**：可点区域 ≥ 64pt；字 ≥ 120pt
2. **少**：一屏一个焦点；学习页只有 3 个决策按钮
3. **有声**：每个动作都有即时声音反馈（点对 = 清脆"叮"，点错 = 温和"再想想"），但全局可静音
4. **不惩罚**：答错不红叉不扣分，说"再看看～"，允许立刻重来
5. **有终点**：每日任务有明确结束画面（今天学完了！+ 得到 1 张贴纸）
6. **护眼**：暖白底 `#FBF7EE`、深灰字 `#2E2E2E`，不用纯白纯黑；20 分钟提示休息
7. **家长区上锁**：删除、改设置、看报告需过算术门（"7 × 8 = ?"）
8. **字体**：汉字用楷体（教学中标准字形，避免黑体误导笔形），拼音用带声调字体

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| OCR 认错字（形近、印刷差、手写） | 强制家长确认页；提供"手动补字"；形近字二次提示 |
| AI 生成的成语/释义有错（最伤信任） | 只生成高频安全内容；成语限定在常用 300 条白名单；每条内容家长可一键编辑，编辑后标记"已校对" |
| 笔顺数据缺失/错误 | 覆盖 3500 常用字即可满足小学；缺失字降级为静态笔顺图；数据源固定版本、可替换 |
| 孩子乱点导致数据混乱 | 家长锁 + 所有破坏性操作二次确认 + ReviewLog 只追加不删 |
| 学习变"打卡任务"失去兴趣 | 每日任务封顶、题型轮换、贴纸收集、周末弹性 |
| TTS 音色机械 | 预留 TTS provider 抽象，可换云端音色批量预生成 |
| 一页信息过载孩子不读 | 折叠分区 + 家长可配置"只显示哪几块" |
